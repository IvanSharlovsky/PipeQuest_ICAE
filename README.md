# ДИЗАЙН-ДОКУМЕНТ (GDD) — КВЕСТ «ТРУБОПРОВОД» ДЛЯ ИЦАЭ / РОСАТОМ

**Версия:** 1.0 | **Дата:** 25.08.2026 | **Движок:** Unity 6.5  
**Платформа:** Тач-панель (сенсорный киоск) | **Время:** до 5 минут  
**ЦА:** Студенты и взрослые без профильного образования (16+)  
**Стиль:** Минималистичный, прототипный — фокус на реализации.

---

## 1. КОНЦЕПЦИЯ

Игрок проектирует две инженерные системы АЭС: **теплоотвод** и **пожаротушение**.  
Сначала запоминает рельеф местности (сканирование), затем drag-and-drop'ом прокладывает трубы от источников к зданиям станции. Системы не должны пересекаться.

### Образовательная цель
Показать, как на АЭС работают независимые инженерные системы: морская вода охлаждает турбину (теплоотвод), а резервуар пресной воды — автономная система пожаротушения.

### Уникальная фишка
Механика **памяти**: после сканирования ячейки скрываются — игрок строит маршрут вслепую, полагаясь на запомненную карту. Это добавляет напряжение и имитирует реальное проектирование без полной информации.

## 2. ЭТАПЫ КВЕСТА (до 5 минут)

| Этап | Название | Действие | Длительность |
|------|----------|----------|--------------|
| 1 | **Сканирование** | Самолёт пролетает над полем ячеек и временно раскрывает тип каждой: проходимая / непроходимая / здание АЭС / источник. Игрок запоминает маршрут. | ~20 сек |
| 2 | **Теплоотвод** | Drag-and-drop: соединить море → блок АЭС цепочкой труб через проходимые ячейки. | ~2 мин |
| 3 | **Пожаротушение** | Drag-and-drop: соединить резервуар пресной воды → здания АЭС аналогично. Системы не должны пересекаться. | ~2 мин |
| 4 | **Проверка** | Тап «Запустить воду» — анимация потока по трубам. Успех, если обе системы соединены без разрывов. | ~30 сек |

## 3. КЛЮЧЕВЫЕ МЕХАНИКИ

### 3.1. Память (сканирование)
- Сетка 10×8 ячеек.
- Самолёт «пролетает» сверху вниз (или по диагонали), последовательно подсвечивая ячейки на 1 секунду каждая.
- После сканирования **все ячейки становятся серыми** — тип скрыт.
- Игрок может ставить **временные маркеры** (тап по ячейке) во время сканирования, чтобы помнить ключевые точки.

### 3.2. Drag-and-drop
- Детали труб (прямые, повороты, тройники) перетаскиваются из **нижней панели** на сетку.
- **Неправильная ячейка** (препятствие) — деталь возвращается на панель с красной вспышкой.
- **Стыковка:** выход одной детали должен совпадать со входом следующей (проверяется при запуске воды).
- **Тап по установленной трубе** — удалить деталь обратно на панель.

### 3.3. Две системы
- **Теплоотвод** (синие трубы): источник — море (нижняя часть сетки), цель — блок АЭС.
- **Пожаротушение** (красные трубы): источник — резервуар пресной воды, цели — здания АЭС.
- **Запрет пересечений:** если трубы систем пересекаются в одной ячейке — ошибка при проверке.

### 3.4. Проверка
- Кнопка «Запустить воду» активна после размещения хотя бы одной детали.
- **Анимация:** вода (светящаяся полоса) движется от источника к цели со скоростью 2 ячейки/сек.
- **Успех:** вода доходит до всех целей, обе системы целы — зелёный баннер + образовательный факт.
- **Ошибка:** вода останавливается на разрыве — красная индикация точки проблемы, текст ошибки («Разрыв в трубе» / «Пересечение систем» / «Препятствие»).

## 4. УПРАВЛЕНИЕ (ТАЧ-ПАНЕЛЬ)

| Жест | Действие |
|------|----------|
| **Тап по ячейке** (при сканировании) | Поставить временный маркер (флажок) |
| **Тап + перетаскивание детали** | Установка трубы на ячейку |
| **Тап по установленной трубе** | Удалить деталь (вернуть на панель) |
| **Тап по кнопке** | Запуск воды / Подсказка / Сброс |

### UX-рекомендации для тач-панели
- **Размер ячейки:** минимум 70×70 px.
- **Размер деталей на панели:** минимум 60×60 px.
- **Зона прилипания:** 50% размера ячейки.
- **Обратная связь:** при захвате деталь увеличивается на 10%, при ошибке — короткая вибрация (если поддерживается) + красная вспышка.

## 5. УСЛОВИЯ ПОБЕДЫ / ПОРАЖЕНИЯ

### Победа
- Обе системы соединены корректно.
- Вода дошла до всех целей.
- Системы не пересекаются.
- **Награда:** экран успеха + образовательный факт.

### Ошибка
- Разрыв в трубе, неправильный поворот, прокладка через препятствие, пересечение систем.
- **Показывается точка проблемы** (мигающий красный круг).
- **2 попытки на исправление:** игрок возвращается к этапу прокладки, может передвинуть/удалить детали.
- После 2-й неудачи — показ правильного маршрута (подсветка) и переход к следующему этапу.

### Тайм-аут
- Если время этапа истекло — автоматический показ правильного решения (подсветка ячеек) и переход дальше.

## 7. UI / ЭКРАНЫ

### 7.1. Экран сканирования
- **Центр:** сетка 10×8.
- **Сверху:** самолёт-иконка, движущийся над сеткой.
- **Таймер:** обратный отсчёт 20 секунд.
- **Легенда снизу:** 4 цвета ячеек.
- **Подсказка:** «Запомните расположение проходимых зон».

### 7.2. Экран прокладки (теплоотвод / пожаротушение)
- **Центр:** сетка (ячейки серые, скрытые).
- **Верх:** название этапа + таймер + счётчик попыток.
- **Низ:** панель деталей (прямая, колено, тройник, вентиль) с количеством.
- **Кнопки:** «Запустить воду» (зелёная), «Подсказка» (оранжевая), «Сброс» (серая).

### 7.3. Экран проверки
- **Анимация:** цветные полосы (синяя/красная) движутся по трубам.
- **При успехе:** зелёный баннер «ОБЕ СИСТЕМЫ РАБОТАЮТ».
- **При ошибке:** красный баннер + мигающая точка проблемы + текст причины.
- **Образовательный блок:** жёлтая плашка с фактом.

### 7.4. Экран результата
- **Успех:** галочка, время, факт.
- **Неудача:** крестик, показ правильного решения, кнопка «Повторить квест».

## 8. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ (UNITY 6.5)

### 8.1. Платформа
- **Движок:** Unity 6.5 (или актуальная LTS-версия на момент разработки).
- **Платформа:** Windows (сенсорный киоск), Android (планшеты) — опционально.
- **Разрешение:** адаптивное 16:9 и 16:10 (1920×1080, 2560×1440).
- **Ввод:** Unity Input System (Touch + Mouse для отладки).

### 8.2. Ключевые системы

| Система | Реализация | Примечание |
|---------|-----------|------------|
| **Сетка** | `GridLayoutGroup` или кастомный `GridManager` | 10×8 ячеек, квадратные |
| **Сканирование** | Корутина + `RevealCell(int x, int y, float delay)` | Последовательное раскрытие |
| **Скрытие ячеек** | `SetCellHidden(bool hidden)` + сохранение типа в `CellData` | Тип хранится, визуал скрыт |
| **Drag-and-Drop** | `IBeginDragHandler`, `IDragHandler`, `IEndDragHandler` | UI-совместимый |
| **Валидация** | BFS/DFS по графу труб + проверка пересечений | Два графа: синий и красный |
| **Анимация воды** | `DOTween` или `LeanTween` + `Image.fillAmount` | Простая анимация заполнения |
| **Сохранение** | `PlayerPrefs` или JSON-файл | Прогресс, лучшее время |

## 9. КОНТЕНТ И АССЕТЫ (МИНИМАЛЬНЫЙ)

### 9.1. 2D-графика (прототип)

- Ячейки: 4 цветных квадрата (проходимая, препятствие, здание, источник).
- Трубы: 4 цветных прямоугольника (синий/красный) + символы (`|`, `└`, `┴`, `⊕`).
- UI: прямоугольные кнопки, панели, текстовые метки.
- Самолёт: простой треугольник + прямоугольник (можно заменить стрелкой).

### 9.2. Анимации

- ScanReveal — ячейка меняет цвет на 1 сек, затем сереет.
- PipePlace — scale 0→1 за 0.15 сек.
- WaterFlow — Image.fillAmount от 0 до 1 за N секунд.
- ErrorBlink — красное мигание ячейки 3 раза.

### 9.3. Звук (опционально на этапе прототипа)

| Событие | Звук |
| --- | --- |
| Сканирование | Короткий «пик» на каждую ячейку |
| Установка трубы | Щелчок |
| Ошибка | Низкий «бум» |
| Успех | Короткий мелодичный сигнал |

### 9.4. Образовательные факты

- «Морская вода охлаждает турбину, а резервуар пресной воды — независимая система пожаротушения АЭС.»
- «Теплоотвод и пожаротушение — две независимые системы, которые никогда не пересекаются на схеме.»
- «При аварии на АЭС система пожаротушения должна работать автономно, без связи с основным контуром охлаждения.»
